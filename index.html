SNAKES_

One game, six languages. Identical rules and palette every time — what changes is how the board gets from source code to your screen.

PICK A RUNTIME

TypeScript

Phaser 3 scenes, a tested game engine module, touch controls and a leaderboard.

PHASER 3 VITE VITEST
PLAY →

Rust

no_std, no wasm-bindgen. A ~3 KB module keeps the board in linear memory; JavaScript reads it and paints.

WASM32-UNKNOWN-UNKNOWN NO_STD
PLAY →

Go

Go owns the whole frame: syscall/js reads the keyboard, drives requestAnimationFrame and draws to the canvas.

GOOS=JS GOARCH=WASM SYSCALL/JS
PLAY →

C

Freestanding clang --target=wasm32: no libc, no emscripten, no runtime. Just static arrays and exported functions.

CLANG NOSTDLIB WASM-LD
PLAY →

Python

Real CPython, compiled to WebAssembly by Pyodide. Dataclasses and random.choice calling into the DOM.

PYODIDE CPYTHON
PLAY →

Elm

No canvas and no draw loop. The board is a value, the view is a pure function of it, and the result is SVG.

ELM 0.19.2 SVG PORTS
PLAY →

Same rules everywhere: a 24×24 board, walls are fatal, the tail is not, ten points an apple and the clock speeds up as you grow. Every version is built from source by GitHub Actions and deployed together.
